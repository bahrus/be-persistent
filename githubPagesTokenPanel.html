1 · Configure a repo + token (Contents: Read and write)

A githubpages:// USL bakes the owner into the string (githubpages://<owner>/<path>, defaulting to the <owner>.github.io repo), so the fields below patch the persisted elements further down before they hydrate. Reading a public repo needs no token; creating/updating a file does.

Get a fine-grained token scoped to just that repo
  1. Open github.com/settings/personal-access-tokens/new.
  2. Set Resource owner to the account above, and under Repository access choose “Only select repositories” → pick the one repo you're testing against.
  3. Under Repository permissions, set Contents to Read and write. Nothing else is needed.
  4. Click Generate token. Copy the value — it starts with github_pat_.
  5. Paste it below and press Save.

A classic token with the broader repo scope also works, if you'd rather not scope it per-repo.

Owner/repo are baked into the persisted elements' USL at load time — save, then reload the page to apply. Revoke the token any time at github.com/settings/tokens.
