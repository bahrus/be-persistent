# Add Nudge Support

## Bruce's Ask

From what I can tell from existing examples, there appears at one point to have been an expectation that [nudge](https://github.com/bahrus/assign-gingerly/blob/baseline/handlers/nudge.ts) was applied in order to enable input elements after hydrating.

Since that got lost in the mix of multiple factorings, let's make it opt in:

```html
<input disabled be-persistent="via locationHash://{autoGenId}." be-persistent-nudge value="hello">
```

If any clarifications are needed first, please list them below.  Otherwise, please implement and add your implementation notes below.

## Implementation Notes

### Status

Done. `npm run build` + `npm run test` green — 5 specs, including a new `Nudge`
spec that proves the opt-in fires (and that a non-opted-in `disabled` element
stays disabled).

### How it works

`be-persistent-nudge` (emoji: `💾-nudge`) is a boolean attribute wired through
the same `withAttrs` mechanism the conversion instructions prescribe for
`nudge`:

```js
// emc.mjs → enhConfig.withAttrs
nudge: '${base}-nudge',
_nudge: { instanceOf: 'Boolean' }
```

`parseWithAttrs` resolves `${base}` against the base attribute, so the emoji EMC
(`💾.json`, generated by `npm run build`) automatically observes `💾-nudge`. The
parsed flag lands on the view model as `self.nudge` (present → `true`, absent →
`false`). It is **not** added to the `hydrate` action's `ifAllOf` / `ifKeyIn`
gates — it just rides along on `self`.

In `hydrate` (`be-persistent.js`), after the `Binder`s are constructed:

```js
if(self.nudge){
    await Promise.all(binders.map(b => b.whenHydrated));
    const {nudge} = await import('assign-gingerly/handlers/nudge.js');
    nudge(enhancedElement);
}
```

`assign-gingerly`'s `nudge(el, 'disabled')` decrements a `disabled` "counter":
`disabled` / `disabled="1"` → attribute removed and `el.disabled = false`;
`disabled="3"` → `disabled="2"`. So it composes with other enhancements that
disabled the same element.

### The one non-trivial bit: `Binder.whenHydrated`

Bruce's phrasing is "enable input elements **after** hydrating", so the nudge
must wait for the value to actually be restored, not just for listeners to be
attached. `Binder`'s constructor already kicks off the initial
storage-reconciliation pass (`handleEvent()` with no event), but previously
discarded the promise. It now stores it:

```js
this.whenHydrated = this.handleEvent();
```

`hydrate` awaits every binder's `whenHydrated` before nudging. This is the only
behavior change to `Binder`; the field is otherwise inert.

### Dependency / wiring

- `assign-gingerly@0.0.96` is already a direct dependency and already in
  `imports.html` (`assign-gingerly/` → `/node_modules/assign-gingerly/`), and it
  exports `./handlers/nudge.js`. No `package.json` / import-map changes needed.
- `nudge.js` is dynamically `import()`ed only when the opt-in is set — zero cost
  for the common case.

### Note

The `Nudge` spec uses `sessionStorage://` (not `locationHash://` as in Bruce's
example) purely to keep it deterministic in headless Chromium — the nudge path
is storage-agnostic. `demo/Nudge.html` keeps the `locationHash://` example as
written.
